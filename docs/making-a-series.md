# 拍一部多集的短剧

一次 `run` 出一集。60 集就是 60 次 run —— 但**不能是 60 个互不相干的项目**，
否则第 2 集的脸就跟第 1 集不一样了。

这篇讲的是那件事：怎么让同一部剧跨集保持同一批脸、同一个声音。

---

## 问题：两集各自都对，合起来是错的

默认（不带 `--project`）的跑法里，角色由分镜阶段的 LLM **每一集重新发明**：

```
第 1 集 -> LLM 造出「苏蔓，31 岁，短发」   -> 生成定妆照 A -> 全集用 A
第 2 集 -> LLM 再造一个「苏蔓，30 岁，大波浪」-> 生成定妆照 B -> 全集用 B
```

关键在于**没有任何一步会报警**：

* 每一集内部是自洽的 —— `stage03_frames` 把同一张定妆照喂给这个角色的每一个
  镜头，所以第 2 集从头到尾都是 B，不会一会儿 A 一会儿 B；
* 质检查的是时长、对白、重复镜头、景别分布，它不知道"苏蔓"应该长什么样；
* `core/faces.py`（谁的脸算准）和 `core/identity.py`（参考锁定）都是**集内**工具，
  它们比较的是同一集的几张候选图，跨集无从下手。

所以这件事只有观众会发现，而发现的时候你可能已经付了 30 集的渲染费。

---

## 做法：一部剧一个 project，角色写进圣经

```bash
# 1. 建剧。这一步不花钱，只写一个 json。
python run.py project new "深夜外卖" --style "冷色调，手持感"
# project_id = proj_1a2b3c4d5e6f

# 2. 每一集都挂上它
python run.py run --project proj_1a2b3c4d5e6f --idea "第1集：暴雨夜送到一栋没人的楼"
python run.py run --project proj_1a2b3c4d5e6f --idea "第2集：她在地下二层听见自己的名字"
python run.py run --project proj_1a2b3c4d5e6f --idea "第3集：……"
```

第 1 集跑完，`projects/proj_1a2b3c4d5e6f/` 就长这样：

```
projects/proj_1a2b3c4d5e6f/
├── project.json          角色圣经（人手可改）
└── portraits/
    ├── 苏蔓.png
    └── 陈默.png
```

第 2 集开始：

* 这两个角色的**外貌描述**取自圣经，分镜阶段的模型怎么改都不算数；
* 这两个角色的**定妆照**直接用上面那两个文件 —— **根本不重新生成**。

第二点是关键。跨集一致性的硬保证不是"提示词写得更像"，而是
**每一集复用同一个文件**。只要那张图还在，第 40 集的脸和第 1 集就是同一张；
而"提示词写得像"只能降低漂移概率，不能消除它。

报告里会如实写出来：

```
[storyboard] [OK] 定稿 4 镜 / 总时长 12.3s / 定妆照 1 张（另有 2 张沿用项目里的，未重复生成）
```

## 角色圣经里有什么

```json
{
  "project_id": "proj_1a2b3c4d5e6f",
  "title": "深夜外卖",
  "logline": "",
  "style": "冷色调，手持感",
  "characters": [
    {
      "char_id": "char_9f3a1c02",
      "name": "苏蔓",
      "aliases": ["蔓姐"],
      "desc": "女，31岁。强势的项目负责人，笑的时候眼睛不笑",
      "anchor_prompt": "……用于生成定妆照的纯视觉提示词……",
      "ref_image": "…/projects/proj_1a2b3c4d5e6f/portraits/苏蔓.png"
    }
  ],
  "voice_map": { "char_9f3a1c02": "female_07" }
}
```

`char_id` 是**身份**，`name` 只是这个身份当下的叫法，`aliases` 是它别的叫法。
分镜里的"这一镜有谁"引用的是身份，所以**改名字不会让前面几集失联** ——
这也是为什么 `voice_map` 按 id 存（改了名字不该换嗓子）。

它是**文件不是数据库**，和 `episode.json` 一个待遇：直接改，下一集生效。

```bash
python run.py project show proj_1a2b3c4d5e6f          # 看圣经 + 这部剧下每一集
python run.py project list                            # 所有剧、集数、角色数
python run.py project set proj_... 苏蔓 --voice female_07
python run.py project set proj_... 苏蔓 --desc "女，32岁，齐耳短发，左手有疤"
```

`project show` 会检查每张定妆照**是不是真的在磁盘上**。圣经里写着路径、
文件却没了，是这里最该被抓出来的一种坏 —— 它会让下一集静默地重新生成一张脸，
而报告里看不出来。

### 改名字、起外号、卧底

三种情况在数据上是同一件事：**身份不动，叫法变了**。

```jsonc
// 把「苏蔓」改名成「苏晚」：先留旧名字，再改 name
{ "char_id": "char_9f3a1c02", "name": "苏晚", "aliases": ["苏蔓", "蔓姐"] }
```

这就是改名该有的写法 —— 旧名字留在 `aliases` 里，前面几集引用它的镜头仍然
锁到同一张脸。手改这个文件完全可以；模型在剧本里自己换了个叫法时，
骨架也会**把那叫法记进别名**（而不是改掉 `name`），下一集按哪个叫法都认得出。

**两个角色同名**（替身戏里很常见）时他们各拿一个 `char_id`。分镜写名字会
**有歧义**，骨架的做法是不猜：那一镜不锁脸，报告里点名。让模型写 id 就能定下来。

## 新角色：圣经是长出来的

第 12 集冒出一个新反派是正常创作，接口不该拦它。新名字这一集正常生成定妆照，
然后**自动写进圣经**（含一个新的 `char_id`）—— 第 13 集开始它也变成"在册角色"，
脸就此固定。

反过来，模型**漏写**一个在册角色也没关系：所有在册角色都会进本集卡司。
漏写是模型最常见的失误，而漏一次这一集就锁不住那个人的脸，代价太大。

---

## 声音也是同一个道理

观众对脸的容忍度比对声音高 —— 换了配音会被直接说成"换人了"。
`voice_map` 把角色名映射到音色：

```json
"voice_map": { "char_9f3a1c02": "female_07", "char_4d81ab77": "male_03" }
```

说话人从台词行首解析（`苏蔓：（低声）不对。` → `苏蔓`）。解析不出来时，如果这一镜
**画面里只有一个人**，就用那个人的音色（走声明，不走文本猜）—— 台词没写说话人
是常见的，退回全局默认会让整部剧听起来像一个人在自言自语。

音色表按 `char_id` 存，但**回落到名字**：手写的圣经一般只写了名字，不能因为
没填 id 就让整部剧换嗓子。

## 每一集多长、粘到哪个平台

两件事按**集**设，不按剧设：

```bash
# 这一集想要 45 秒；均摊到 4 个镜头是每镜 11.25 秒
python run.py run --project proj_1a2b3c4d5e6f --idea "第3集：……" --target 45

# 只出提示词（不出片）：同一部剧、同一批角色，按可灵的框整理
python run.py prompts --idea "第3集：……" --project proj_1a2b3c4d5e6f \
    --dialect kling --json 第3集-提示词.json
```

`--target` 是**愿望不是保证**：台词读不完的镜头会突破上限，报告里写
`总时长 47.0s（目标 45s，多 2.0s）`。要更接近就加镜数，或者把台词改短 ——
这是创作决定，不该由公式悄悄替你做。

同一部剧建议**一个方言用到底**：可灵的框、即梦的框在一部剧里不会变，
换来换去只会让第 5 集的提示词和第 4 集长得不一样。

---

## 出错了会怎样

**打错 project_id 会当场停下**，不会静默降级成"每集重新造角色"：

```
$ python run.py run --project proj_typo --idea "..."
project 不存在：proj_typo
```

`project.json` 写坏了（比如手改时少了半个括号）同样会抛，**不会**被当成
"这个项目没有角色" —— 那等于把一部 60 集的片子悄悄变成每集重新投胎，
而且要跑到第 2 集成片才看得出来。

## 已知边界

* **只包住角色。** 场景/地点、同一角色在不同集的换装还没有对应机制
  （`Scene.location` 目前每集自由生成）。要加的话是同样的形状：在 Project 里
  放一个 `locations` 字典 + 可复用的场景参考图。
* **按身份匹配角色。** 谁在画面里由分镜阶段显式声明（`Shot.characters`），
  而声明里写的是**引用**：优先角色 id，写名字或别名也认（会在报告里记成降级）。
  改名不会让前面几集失联，同名不同人不会被折成一个人 —— 详见
  [architecture.md](architecture.md) 的「名字是叫法，不是身份」。
  剩下的边界：模型既没给 id、又把名字写错一个字时，那会被当成一个新角色入册。
  刻意的（模糊匹配会把「朱锦」和「朱锦娘」合成一个人），报告里"新入册 N 个"是信号。
* **定妆照换了，已经跑过的集不会自动重渲。** `project set --anchor-prompt`
  会提醒你删掉那张图再跑；但要让旧集也换脸，得 `--force` 重跑它们的
  `storyboard` 起的部分（钱重新花）。
* **剧本层面的连续性不在范围内。** "上一集那个人死了没有"这类问题由你
  在 `--idea` 里交代，圣经只管"他长什么样、说话什么声音"。
* **时长按集算，不按剧算。** 没有"全剧 30 集一共 25 分钟"这种配额，也没有
  跨集平衡（这集超了 20%，下集自动少 20%）。要多集总量可控，就把每集的
  `--target` 报出来自己记账：`python run.py runs` 里每集的实际时长都在。
* **方言（可灵/即梦/海螺…）不影响出片。** 它只是把同一批提示词换个排版，
  方便你粘到网页端；走 API 出片时用不到它，也就没有"某家方言必须配某家 provider"
  这回事。
