# 06 · 质检（QC）

> 目标不是"判断好不好看"（这没法自动化），而是把**能判定的事情全部判掉**，
> 让人的注意力只花在真正的创意判断上。

## 自动化能查的（骨架负责，跑完即出报告）

### 结构性
- [ ] 成片时长落在 **45–90 秒**
- [ ] 所有片段**分辨率一致**（默认 720×1280）、**帧率一致**（默认 30）
- [ ] 关键帧总数 == 分镜表镜头总数
- [ ] 没有任何镜头处于 `failed` 或 `pending` 状态

### 音画
- [ ] 每条有台词的镜头都有对应 `shot_NNN_audio.wav`
- [ ] 每段音频时长 ≤ 该镜时长（超了会被截断 = 台词没说完）
- [ ] 成片有音轨，且音轨时长 ≈ 视频时长（差 < 0.5s）
- [ ] 没有静音段（全片 RMS 不出现连续 > 3s 的静默）

### 成本
- [ ] 总花费 ≤ 预算
- [ ] **没有任何镜头的成本为 0**（0 成本 = 大概率走了假数据或缓存异常）
- [ ] 成本明细里每一项都对应一次真实调用（`calls` 数量与日志一致）

### 一致性（需要参考图才能查）
- [ ] 每个有 `characters` 登记的角色，至少在一张关键帧里出现过
- [ ] 同一角色在不同关键帧里的面部相似度 ≥ 阈值（用定妆照做基准）

## 只能人工判断的（skill 负责，输出给成人看）

- 前三秒够不够抓人
- 转折有没有力度
- 结尾的钩子会不会让人想评论
- 台词是否自然（模型写的中文常有翻译腔）
- 节奏是不是中段塌了

## 输出契约

```json
{
  "verdict": "pass | warn | fail",
  "checks": [
    {"name": "duration_range", "ok": true, "detail": "62.4s"},
    {"name": "audio_alignment", "ok": false,
     "detail": "sc01/shot_002 音频 5.2s > 镜头 4.0s，台词被截断"}
  ],
  "blocking": ["audio_alignment"],
  "advisory": [
    "中段第 6–9 镜都是 close，景别重复，建议打散",
    "结尾台词「我知道是你」偏直白，可改成动作收尾"
  ]
}
```

`blocking` 是必须修的，`advisory` 是可选的。
**verdict 只由 `blocking` 决定** —— 不要因为"感觉不太好"就判 fail，
那样这个字段会失去意义。

## 修复优先级

发现问题后按这个顺序修，因为成本递增：

1. 时长/景别/台词问题 → 改 `episode.json`，`resume` 只重跑后面的阶段（几乎零成本）
2. 单镜画面问题 → 删那个镜头的产物文件，`resume` 只重抽那一镜
3. 角色不一致 → 回去改 `04-character-bible.md` 的身份词块，然后**全部重跑**
4. 剧本层面问题 → 回到 `02-screenwriter.md`，这是最贵的

```
你是短剧质检员。审查下面这份分镜表和自动质检报告，指出问题。

分镜表：{episode_json}
自动报告：{qc_report_json}

要求：
- 严格区分 blocking（必须修）和 advisory（建议）
- 每条问题必须**指到具体镜号**，不许说"整体节奏偏慢"
- 不要因为主观审美判 fail，verdict 只由 blocking 决定
- 中文台词请明确指出翻译腔

只输出 JSON，结构见 skills/06-qc.md 的「输出契约」。
```
