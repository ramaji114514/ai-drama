# 00 · 流水线总纲

## 这一层的职责边界

```mermaid
flowchart LR
    A[一句话想法] --> B[01 选题]
    B --> C[02 剧本]
    C --> D[03 分镜]
    D --> E[04 角色卡]
    E --> F[05 镜头提示词]
    F --> G[骨架: 关键帧]
    G --> H[骨架: 视频片段]
    H --> I[骨架: 配音]
    I --> J[骨架: 拼接/转码/字幕]
    J --> K[06 质检]
```

**斜线左边是创意（本目录），右边是确定性流程（`ai_drama/`）。**
骨架只做两件事：把 JSON 变成文件、把文件按顺序拼起来。

## 四个真正的难点（按难度排序）

### 1. 角色一致性 —— 最致命
同一个角色在 20 个镜头里必须长得像同一个人。目前唯一可用的手段是
**首帧参考图（image-to-image / 定妆照）+ 身份词块**，见 `04-character-bible.md`。
纯文生视频做不到这一点，所以骨架给每个镜头都留了 `ref_image` 入口。

### 2. 镜头级可控性
不能"整片重抽"。必须做到**每镜一次生成、失败单独重试、其他镜不受影响**。
骨架的实现方式：每个镜头的产物落盘 + 状态写库，`resume` 时只重跑失败的镜。

### 3. 成本与时长
一条 60 秒的竖屏短剧，按当前视频模型价格量级要 5–20 美元。
所以骨架**必须**有：缓存（同 prompt 不重复调用）、成本记账（精确到镜）、
预算闸门（超了抛异常而不是偷偷降级）。这三件事骨架已经做了。

### 4. 评测自动化
"这条片子好不好"没法用代码判断，但**可以判定的东西很多**：
- 时长是否落在 45–90 秒
- 台词是否都有对应音轨、音画是否对齐
- 每个角色是否都在关键帧里出现过（用参考图做相似度即可）
- 分辨率/帧率/宽高比是否统一（竖屏 9:16）
把这些做成 `06-qc.md` 的清单，骨架跑完自动出一份报告。

## 输出契约（所有 skill 通用）

每个 skill 产出**合法 JSON**，字段名与 `ai_drama/core/models.py` 对齐。
最关键的三个对象：

```json
// Shot
{"order": 0, "framing": "close", "action": "...", "dialogue": "角色：台词",
 "location": "老城区出租屋", "duration_sec": 3.2}

// Scene
{"scene_id": "sc01", "title": "...", "summary": "...", "location": "...",
 "time_of_day": "深夜", "shots": [ /* Shot[] */ ]}

// Episode
{"title": "...", "logline": "...", "style": "...",
 "characters": [{"name": "...", "identity_tokens": "...", "voice": "female_01"}],
 "scenes": [ /* Scene[] */ ]}
```

**不确定的字段宁可省略，不要编造。** 骨架对缺失字段有默认值，
对编造的字段会直接崩。

## 铁律

1. **不要写死厂商名字。** 提示词里不要出现"用可灵/即梦生成"，只描述画面。
   厂商是骨架的依赖注入点，不是创意的约束。
2. **不要输出厂商参数。** 分辨率、帧数、guidance scale 由骨架按 provider 能力翻译。
3. **时长要给数字。** "大约 3 秒"不行，要 `"duration_sec": 3.2`。
   拼接是按累计时长做的，估错会让音画不同步。
