# skills —— 创意判断层

这个目录里放的是**提示词与判断标准**，不是代码。

## 为什么和代码分开

一句话：**按"会不会变"切。**

| 层 | 放什么 | 特征 |
|---|---|---|
| `ai_drama/`（骨架） | 状态机、断点续跑、成本记账、ffmpeg 拼接/转码/字幕烧录、并发调度 | 确定性流程，不该让 LLM 每次重新发明 |
| `skills/`（本目录） | 选题、剧本、分镜设计、角色设定、镜头提示词、质检标准 | 创意判断，随品味迭代，写死在代码里会僵化 |

两者通过**结构化产物**对接：skill 产出 JSON，骨架消费 JSON。
中间那份 `runs/<run_id>/episode.json` 就是契约 —— 你可以手改它然后 `resume`，
骨架会照着你改过的分镜继续跑。

## 目录

| 文件 | 环节 | 产出什么 |
|---|---|---|
| `00-pipeline.md` | 总纲 | 十二环节流水线、四个真正的难点、责任划分 |
| `01-showrunner.md` | 选题 | 一句话 → 卖点 / 钩子 / 前三秒 / 标题 |
| `02-screenwriter.md` | 剧本 | 想法 → 分场分镜表（`episode.json` 的 `scenes`） |
| `03-storyboard.md` | 分镜 | 景别 / 机位 / 表演节拍 / 时长 |
| `04-character-bible.md` | 角色一致性 | 角色卡（身份词块，跨镜头复用） |
| `05-shot-prompt.md` | 镜头提示词 | 每镜的图像提示词 + 视频提示词 |
| `06-qc.md` | 质检 | 一致性 / 节奏 / 音画对齐的验收清单 |

## 用法

**人用**：写新剧本前读 `00-pipeline.md`，然后按 `01 → 02` 往下走。

**agent 用**：把对应 skill 文件全文塞进 system prompt，再喂输入。
每个 skill 末尾都写了输入/输出契约，输出必须是合法 JSON，骨架才吃得下。

**改进 prompt**：直接改这里的 md 文件。改完重跑 `python run.py run --force`
就能看到效果 —— 这就是把创意层从代码里拆出来的意义。
